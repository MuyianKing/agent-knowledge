# 通用 CURD 页面

用于根据接口文档和业务字段要求，实现完整的前端 CURD 页面。该 skill 不绑定具体框架、组件库、目录结构、命名方式或项目文件名，所有实现细节必须先适配目标项目的现有规范。

## 触发条件

当用户提出以下需求时调用：

- 新增一个 CURD 页面
- 根据接口文档生成查询、列表、新增、编辑、删除功能
- 模仿项目中已有的 CURD 页面
- 自定义列表列、表单项或字段联动
- 完善已有业务页面的 CURD 能力

## 执行流程

1. 读取目标项目的规则、依赖、请求封装、路由和现有 CURD 页面。
2. 确认接口文档、查询字段、列表字段、表单字段和字段联动关系。
3. 根据目标项目现有模式确定页面、表单、接口服务和模型的拆分方式。
4. 整理字段清单，明确字段类型、默认值、枚举、校验和展示方式。
5. 实现查询区域、列表区域、操作区域、编辑表单和接口服务。
6. 根据需要实现列表列自定义、表单控件自定义和字段联动。
7. 验证新增、编辑、删除、查询、刷新、回显、校验和异常流程。
8. 按目标项目已有命令执行格式检查、构建和测试；没有测试配置时明确说明。

## 前置确认

接口或字段信息不完整时，先向用户确认，不猜测以下内容：

- 接口地址、请求方式和参数结构
- 新增与编辑是否共用接口
- 删除接口的参数形式
- 分页参数和返回结构
- 查询条件及顺序
- 列表字段及顺序
- 新增/编辑字段及顺序
- 字段类型、枚举、默认值、必填和校验规则
- 是否存在树形数据、父级字段或远程选项
- 需要自定义展示的列表字段
- 需要自定义控件的表单字段
- 字段之间的显示隐藏、清空或联动规则

## 实现边界

遵循目标项目已有结构。通常可以拆分为以下职责，但不得强制使用这些名称或文件：

- 列表页面入口：查询、列表、操作、刷新和弹窗打开
- 编辑表单组件：新增、编辑、表单校验和自定义控件
- 接口服务模块：列表、新增、编辑、删除请求
- 数据模型：表单字段初始化、默认值和编辑回显

优先复用目标项目已有的：

- 分页列表 Hook 或请求 Hook
- 查询组件
- 表格组件
- 弹窗和表单组件
- 消息提示组件
- 字典、枚举和远程选择组件
- 请求封装和错误处理机制

不要因为实现 CURD 而引入新的组件库、状态管理、请求库或格式化体系。

## 字段处理原则

将字段明确分为三类：

- 查询字段：只用于筛选列表数据
- 列表字段：用于表格展示
- 表单字段：用于新增和编辑

同一个字段可以属于多个类别，但每种用途的配置要分别确认，不能因为字段出现在接口中就自动放入查询、列表或表单。

默认值按以下优先级确定：

1. 接口文档明确的默认值
2. 项目现有业务约定
3. 字段类型和是否允许为空
4. 用户确认后的业务规则

类型默认值只能作为技术兜底，不能替代业务约定。枚举、状态、类型、父级标识、排序等字段尤其不能凭经验猜测。

## 列表自定义

普通字段使用项目表格组件支持的列配置。需要转换或复杂展示的字段使用项目已有的列插槽、渲染函数或列组件。

常见自定义场景：

- 枚举值转换为中文文本
- 状态显示为标签、开关或图标
- 日期、金额、百分比格式化
- 图片、头像、链接或组合字段
- 树形名称或层级缩进
- 自定义表头
- 操作列增加编辑、删除、详情、子项等按钮

自定义列时必须保持原始字段和展示字段的职责清晰；除非项目已有约定，不要为了显示文本修改接口原始数据。

## 表单自定义

普通输入字段使用项目表单配置。下拉、单选、日期、数字、上传和远程选择等控件使用项目已有组件及其属性配置。

当标准表单配置不能满足需求时，按以下顺序选择：

1. 使用已有表单组件的配置项
2. 使用字段级插槽或渲染能力替换内部控件
3. 使用自定义表单项完全控制标签、校验和控件
4. 只有多个页面都需要时，才考虑扩展通用表单能力

自定义表单项必须保证：

- 表单值仍然写入统一的表单对象
- 字段名与接口参数保持一致或在服务边界明确转换
- 校验规则仍然能被表单提交流程执行
- 编辑数据能够正确回显
- 保存成功后沿用项目现有关闭和刷新机制

## 字段联动

当一个字段依赖另一个字段显示或隐藏时，同时处理：

- 显示条件
- 隐藏时的校验规则
- 切换条件后的旧值清理
- 提交时的字段过滤或转换
- 新增和编辑场景的初始状态

不要只通过视觉隐藏字段而保留无效值提交。例如类型字段变化后，已不适用的路由、组件、权限或关联字段应根据接口约定清空或移除。

## 接口服务要求

保存函数必须接收表单数据并返回项目请求封装返回的 Promise，使表单提交流程能够等待成功或失败。

新增和编辑的判断方式必须以接口文档为准：

- 如果接口共用且通过标识字段区分，按接口约定处理
- 如果新增和编辑是不同接口，分别封装
- 如果接口要求特定参数转换，在接口服务边界转换
- 页面和表单组件不要直接创建请求实例

删除成功后刷新列表；新增或编辑成功后按照项目现有弹窗和列表刷新机制处理。

## 特殊数据结构

遇到树形、级联、远程选项、批量操作、关联数据或非标准分页时，先确认接口数据结构和现有组件能力，再决定实现方式。

不要仅凭字段名称推测：

- 父级值是否代表根节点
- 数据是否已经是树形
- 删除父节点是否允许存在子节点
- 远程选项的请求参数和回显方式
- 列表是否支持树形展开

## 最终自检

- [ ] 接口地址、请求方式和字段均来自文档或用户确认
- [ ] 查询、列表和表单字段职责清晰
- [ ] 模型默认值符合类型和业务约定
- [ ] 新增和编辑数据能够正确初始化与回显
- [ ] 自定义列表列显示正确
- [ ] 自定义表单控件能够回写和提交
- [ ] 字段联动同时处理显示、校验、清理和提交
- [ ] 保存函数返回可等待的 Promise
- [ ] 保存、删除后列表按项目规则刷新
- [ ] 已执行目标项目可用的检查命令，并如实报告结果
